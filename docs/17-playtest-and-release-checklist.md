# 真人试玩与发布清单

以下是下一步需要实际执行的验证，不能用本机自动测试代替。

## 第一轮试玩

建议邀请至少三组塔防新玩家和三组有经验玩家，分别完成前三关与至少一关地图机关关。先让玩家独立操作，记录求助位置，再收集反馈。用设置中的本地反馈导出记录；发送文件前由玩家确认文字中没有个人信息。

记录：首次建塔耗时、首关失败原因、是否理解三级分支、塔技能施放次数、金币长期闲置、双方谁在包办、失败后是否能说出下一次调整办法。不要只比较胜率，还要询问节奏、画面拥挤、声音疲劳和是否愿意重玩。

判定建议：新玩家应能不用口头指导完成建塔与准备；双方都能指出自己的职责；输掉后能提出至少一项有效调整。若某条分支在不同地图上都被优先选择，先检查价格、覆盖范围和功能，再决定削弱或补强其他路线。

## 真实联机

| 场景 | 操作与通过条件 | 当前状态 |
|---|---|---|
| 两台物理电脑同一局域网 | 房间码、发现、加入、十波、双方相同结算和星级 | 待验证 |
| 不同网络直连 | 明确端口可达，再测试加入；记录失败原因 | 待验证 |
| 不可达地址 | 十二秒内结束等待，允许重新建房或加入 | 本机规则验证通过 |
| 延迟与丢包 | 100/200ms 延迟、1%/5% 丢包；无重复扣费与不同步 | 待真实网络条件验证 |
| 临时断网与恢复 | 暂停、原席位重连、恢复技能和权限、继续结算 | 本机重连通过；物理断网待验证 |
| 版本不一致 | 拒绝加入，诊断配置哈希不同 | 已有本机回归；双机待验证 |

跨网邀请便利性仍取决于中继或平台网络服务。当前没有公网中继；不能在宣传中承诺任意网络一键联机。选择托管方案后再实现和验证，不以房间码代替网络穿透。

## 兼容性与稳定性

- 使用没有安装 Godot 的干净 Windows x86_64 电脑验证解压、启动、退出、再次启动与存档。
- 测试 1280×800、1920×1080、2560×1440，及 Windows 125%/150%/200% 缩放；输入位置和菜单不得错位。
- 在集显或低端独显上测试最终波、全部塔、低/中/高特效，记录帧率、内存和卡顿。当前没有经过验证的最低配置。
- 连续完成或重开二十局，检查内存增长、声音声部、报告大小、旧倒计时和连接释放。
- 保留测试存档副本，验证旧版升级、主文件损坏恢复、两份都损坏和磁盘写入失败。

## 关卡与商品包装

基础战役通过真人调校后，再决定挑战条件和额外难度，避免直接增加内容掩盖节奏问题。检查每关是否有明确战术主题，以及准备期、最后几只敌人和结算是否拖长。

应用图标与正式导出已完成。商店胶囊图、宣传片、准确平台说明、反馈渠道、定价与素材许可清单仍需发布时准备。只有实际支持和验证过的联机、平台、控制方式才能列入商品承诺。商店提交前冻结候选构建，保存校验清单、验证记录和可回退的上一个包。
